Your build checklist

0 of 8 done

1. Choose your project

Pick something small, real and useful to you. A finished small site beats an unfinished big one. Three good first projects:

ProjectGood forWhat it has
Personal homepageStudents, professionals, creatorsAbout you, skills or work, projects, contact links
Small business pageShops, tutors, home bakers, freelancersWhat you sell, prices or menu, timings, location map link, WhatsApp button
A useful mini toolEveryoneA trip expense splitter, EMI calculator, study timer, recipe box or chore chart

Tools that only work inside the page (calculators, timers, checklists) are perfect for a first build: no accounts, no servers, no cost.

2. Write a one-page brief

The biggest difference between a messy result and a great one is the brief. Let AI interview you and write it:

The brief builder
I want to build a simple website with AI's help. I'm not a programmer. Interview me one question at a time (maximum 8 questions) about: who it's for, the one thing a visitor should do, the sections I need, the content I already have, the look and feel I like (colours, examples of sites I admire), and whether it needs to work in Tamil or another language. Then write a one-page website brief I can give to an AI website builder.

Save the brief in a note. You'll reuse it every time you start a new chat.

3. Generate the first version

Choose a route. Both are free to start.

Recommended

Route A: one file with your assistant

Ask Claude, ChatGPT or Gemini for a single HTML file. You own it completely, it publishes free forever on GitHub Pages, and it works with this whole guide.

Easiest

Route B: an AI app builder

Lovable, Bolt or Replit build and host the site for you, with one-click publishing. Great for apps with logins or databases. Free plans have limits.

Route A: the build prompt
Build this website as ONE self-contained HTML file (HTML, CSS and JavaScript together, no external files except Google Fonts).

[paste your brief here]

Requirements:
- Works well on mobile first, then desktop
- Clean, professional design with a clear colour palette and good fonts
- Accessible: readable contrast, alt text for images, buttons big enough to tap
- Include a page title and a meta description for Google
- No placeholder text: write real content from my brief, and mark anything I must replace with [REPLACE]
- No secret keys, passwords or tracking code

Give me the complete file in one go, then a short list of what I should check.

Using Route B? Paste the same brief into Lovable, Bolt or Replit, and skip to step 5. Their Publish button replaces step 7.

4. Preview it

  • On a laptop: copy the code into a plain text editor (Notepad on Windows, TextEdit in plain-text mode on Mac), save it as index.html and double-click it. It opens in your browser.
  • On a phone: many assistants show a live preview of the page (look for a preview or "artifact"/"canvas" view). You can also skip ahead to step 7: GitHub lets you create the file directly in the mobile browser, and your live link becomes the preview.
  • Check it on both a phone and a big screen. Most problems show up on one but not the other.

5. Improve it in rounds

Vibe coding is a loop: look, describe what's wrong, get a new version. Change one or two things per round, and always ask for the complete updated file so nothing gets lost.

Fix something
On my phone, [describe exactly what you see, or attach a screenshot]. It should [what you expected]. Fix only this, keep everything else the same, and give me the complete updated file.
Make it look professional
Act as a senior web designer. Review this page and list the 7 changes that would make it look most professional: spacing, typography, colour, alignment, consistency, mobile layout. Then apply them and give me the complete file.
Add a feature
Add [feature, e.g. a "Chat on WhatsApp" button linking to wa.me/91XXXXXXXXXX with a prefilled message / a dark mode / a simple FAQ section]. Keep the current design. Give me the complete file.
Save every version. Name them index-v1.html, index-v2.html and so on. If a change breaks things, go back one version instead of fighting the AI.

6. Check before launch

Ask the AI to review its own work, then go through the checklist yourself.

Launch review
Review this website before I publish it. Check: broken links, text that is too small or low-contrast, layout problems on small phones, missing alt text, spelling, missing page title or description, anything that could be a privacy or security risk, and any [REPLACE] placeholders I forgot. List problems by importance, then give me the fixed complete file.
  • Every [REPLACE] is replaced with real content
  • Phone numbers, email and links are correct (tap each one)
  • It looks right on a small phone and on a laptop
  • No personal details you wouldn't put on a public notice board
  • No passwords, API keys or private data anywhere in the code
  • Prices, timings and claims are accurate and current
  • Images are yours, or free to use, and every AI-made image of a person is clearly not a real customer

7. Publish it free on GitHub Pages

GitHub Pages hosts simple websites free, with HTTPS, as long as you like. This works in a phone browser too.

  1. Sign up at github.com/signup and verify your email. Your username becomes part of your address: username.github.io.
  2. Create a repository: tap + → New repository. Name it (for example my-site), choose Public, and tick Add a README. Create it.
  3. Add your page: tap Add file → Create new file, name it exactly index.html, paste your code, then Commit changes. (On a laptop you can use Upload files instead.)
  4. Switch on Pages: open Settings → Pages. Under "Build and deployment", choose Deploy from a branch, branch main, folder / (root), and Save.
  5. Wait 1–2 minutes and refresh. A box shows "Your site is live at https://username.github.io/my-site/". Open it on your phone. You're on the internet.

To update later: open index.html in your repository, tap the pencil icon, paste the new version, and commit. The live site updates in a minute or two.

Prefer drag-and-drop? Netlify Drop publishes a folder in seconds; sign in and claim the site so it stays online.

8. Add your own domain (optional)

A name like yourname.in looks more professional. A .in domain usually costs a few hundred rupees in the first year; check the renewal price too.

  1. Buy the domain from any registrar (GoDaddy, Hostinger, Namecheap, Cloudflare). Skip the add-ons. Complete any KYC or email verification they ask for; the domain won't work until then.
  2. In the registrar's DNS settings, delete any "Parked" A record and domain forwarding, then add four A records for @: 185.199.108.153, 185.199.109.153, 185.199.110.153, 185.199.111.153, and a CNAME for www pointing to username.github.io.
  3. In GitHub: Settings → Pages → Custom domain, type your domain and save. When the DNS check turns green (minutes to a day), tick Enforce HTTPS.

Add the custom domain in GitHub only after the domain is active and the DNS records are in, or your github.io link will redirect to an address that doesn't work yet.

9. Get found, and keep it fresh

  • Share it: WhatsApp status, Instagram bio, LinkedIn, your email signature, a QR code on your shop counter.
  • Google: add your site to Google Search Console so Google finds it. Businesses should also claim a free Google Business Profile.
  • Keep it current: a page with last year's prices hurts trust. Put a monthly reminder in your calendar to check it.
  • Ask for feedback: watch one person use it without helping them. Fix what confuses them.

Common problems and fixes

ProblemWhat to do
The AI's answer stops halfway through the codeSay "continue exactly where you stopped". If it keeps happening, ask it to make the page shorter, or split it into steps.
A fix breaks something elseGo back to your last good version. Ask for one change at a time and the complete file each time.
Looks fine on laptop, broken on phoneSend a phone screenshot and say "fix the mobile layout without changing the desktop design".
GitHub shows a 404 pageCheck the file is named exactly index.html (lowercase), Pages is set to the main branch and / (root), and wait two minutes.
Changes don't show on the live siteWait two minutes, then refresh hard (or open in a private window). Browsers cache old versions.
A contact form doesn't send anythingA plain web page can't send email by itself. Use a WhatsApp or email link, or a form service such as Google Forms.
The AI keeps "improving" things you likedSay clearly "do not change anything else", and paste only the part to change.

Level up

Once your first site is live, here's how to grow from vibe coding to real building skills:

  1. Read your own code. Ask AI: "Explain this file section by section, like I'm new to HTML." You'll learn faster from your own site than from any tutorial.
  2. Learn the basics properly: HTML, CSS and JavaScript on MDN Learn, the free standard reference.
  3. Multi-page sites and Git: add more pages, and learn how GitHub keeps every version of your work.
  4. Apps with data: when you need logins or a database, try Lovable, Replit or Supabase, and learn why secret keys must never go in front-end code.
  5. AI coding agents: tools such as Claude Code and Cursor work inside your project folder and can handle bigger builds. They reward people who understand the basics.
